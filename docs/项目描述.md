# SpringCat：项目描述与技术选型

> 文档版本：v1.3  
> 更新日期：2026-09-17  
> 项目代号：`springcat-ai`  
> 目标平台：Windows 10/11、macOS 12+  
> 本版重点：产品是 vibe coding 桌面工具台；下一刀工作模式能力是本机供应商 / Key 管理，云端备份后置。不把外部工具嵌成子应用。  
> 实现步骤见 [springcat-ai-v1.md](./springcat-ai-v1.md)

## 1. 项目概述

SpringCat 是给热爱 vibe coding 的人用的桌面工具台。它不替代 Cursor、Codex、Grok、Gemini 这些对话窗口，而是补上这群人在多工具、长任务、来回切换里真正卡住的地方：先把工具接进日常、把 Key 和供应商改对，再看见它们在干什么，必要时跳回现场，并看清用量。

两种展示形态共用同一套任务模型和桌面入口：

- **工作模式（MVP 先做）**：不使用宠物形象，用一块可拖动、可吸附的工作面板（紧凑状态卡片，不是全屏遮罩式模态）贴在屏幕顶部或左右侧边。
- **宠物模式（后续再做）**：一只可吸附在屏幕边缘的桌面宠物，用表情、状态灯和消息气泡提醒。

核心价值：

> 让 vibe coding 更容易上手，也更容易撑过一次长任务。任务监听是第一项已交付能力；供应商 / Key 管理是下一刀要兑现的上手能力。后续能力必须挂在同一个安静、低干扰、可长期停留在桌面边缘的入口上。

### 1.1 给谁用

- 已经在用、或正准备用多个 AI 编程工具，希望少踩安装、绑定、换 Key、换供应商的坑。
- 习惯把任务丢给 Agent 后去做别的事，回来时需要一眼知道谁做完了、谁在等确认、该回哪段对话。
- 在 vibe coding 过程中会同时关心进度、中断和 Token / 费用，但不想为每个工具单独开一套监控和配置器。

### 1.2 当前用来兑现定位的能力

- **上手（监听）**：设置页一键绑定 Codex、Cursor、Grok CLI、Gemini CLI、WorkBuddy、Marvis 等来源；合并写入用户级 hooks，不覆盖其他工具已有配置；启动时检查并修复已启用的绑定。
- **过程中看见**：统一展示开始、进度、等待、完成、失败和取消；离开对话窗口后仍能收到低干扰提醒。
- **回到现场**：打开任务 deep link，或回到对应的来源应用。
- **看清消耗**：从本地结构化日志汇总 Token 用量，按日、周、月查看趋势、模型分布与费用估算。

后续工具台能力可以继续解决 vibe coding 的上手问题和过程问题，但必须共享同一入口、同一套通知优先级，并且默认本地优先。不能每增加一个功能就增加一个浮窗，也不能改成聊天客户端，也不把 CC Switch 或其他外部应用嵌成子应用。同类能力在 SpringCat 里原生实现。

### 1.3 下一刀：供应商与 Key 管理

这是工作模式里下一项要做的上手能力，不依赖宠物模式。分阶段计划见 [provider-switch.md](./provider-switch.md)。

用户要能在 SpringCat 里为已支持的 CLI 保存多套供应商配置（名称、Base URL、API Key），并一键写回对应工具的本机配置。切换后，该工具下一次请求走新的 Key / 上游，而不用手改 JSON、TOML 或 `.env`。

约束：

- 第一期覆盖 **Codex、Gemini CLI、Grok CLI**。这些工具的 Key / Base URL 就在用户家目录配置里，和现有适配器安装是同一类写入。
- Cursor、WorkBuddy、Marvis 第一期不做 Key 切换；它们不是靠改一份本地 API Key 文件来换上游。
- 配置写入必须原子化，切换前备份，失败可回滚。SpringCat 自己的 hooks 不得被这次写入清掉。
- API Key 只保存在本机 SpringCat 数据目录的供应商库里，并在切换时写入目标工具配置。密钥不进入任务事件、inbox、用量库或 UI 日志。
- 界面默认遮罩 Key，需要用户显式显示。
- 托盘可切换当前供应商，不必打开完整设置窗口。
- 第一期不实现本地反向代理、故障转移，也不为改 Key 新开 HTTP 端口。用户如果用中转，把中转的 Base URL 和 Key 当作一套供应商保存即可。

### 1.4 更后：可选云端备份

云端备份是后续能力，不是第一期 Key 管理的前置条件。本机切换必须在没有云账号时完整可用。

以后要做时：

- 默认仍然只存在本机。云端备份必须用户显式打开。
- 备份对象是 SpringCat 自己的数据：设置、供应商配置（含 Key）、任务生命周期元数据、用量汇总。不备份完整对话、推理、工具结果或项目源代码。
- Key 若上传，必须加密；不能把明文 Key 写进普通同步盘文件。
- 云同步不能变成社交、商城或账号体系的主体。它只是换机和防丢失。

### 1.5 非目标

- 不实现宠物形象、Rive 角色动画或宠物皮肤（工作模式 MVP）。
- 不复制 Codex / Cursor / Grok 的完整聊天界面。
- 不读取或上传完整项目代码。
- 不轮询聊天窗口、不截屏识别、不开放本地 HTTP 端口收事件。
- 不做养成、商城或社交。
- 不把 CC Switch 或其他外部桌面应用嵌进 SpringCat。
- 不承诺盖过全屏游戏。
- 工作面板不是阻塞整屏的模态。

## 2. 展示模式

```ts
type PresentationMode = "work" | "pet";
```

默认 `work`。两种模式共用事件、仓库、优先级和通知策略，只替换展示层。领域层不得出现宠物专用字段。

## 3. 状态优先级

```text
waiting > failed > completed-unread > running > idle
```

由纯函数计算：

```ts
function deriveSurfaceState(tasks: TaskItem[]): SurfaceState
```

工作模式表现：

- 执行中：暖黄状态点，不弹摘要
- 等待确认：琥珀色，探出且不自动消失
- 已完成：薄荷绿，约 5 秒收起并留未读点
- 失败：珊瑚红，摘要不自动消失

常驻入口只呈现当前最重要的一件事。完整历史、设置、供应商配置和用量等长内容进入用户主动打开的工作台，不把整个产品信息架构塞进胶囊。

## 4. 技术栈

```text
桌面外壳        Tauri 2
前端            Svelte 5 + TypeScript + Vite
工作面板 UI     HTML / CSS（MVP 唯一展示层）
宠物动画        Rive Canvas Lite（仅宠物模式，后置）
本地核心        Rust
本地存储        SQLite
```

事件链路：工具 hooks → `springcat-bridge` → inbox 文件 → Rust 监听/规范化/入库 → Tauri event → Svelte 展示层。

供应商链路：SpringCat 本机供应商库 → 原子写入目标工具配置 → 该工具自行读取新的 Key / Base URL。

## 5. 窗口与吸附（工作模式）

- 默认一个常驻 WebView，约 `360×48` 收起。
- 可吸附 **顶部 / 左侧 / 右侧**，避开任务栏、Dock、菜单栏。
- 不支持底部吸附。
- 设置窗口按需创建，关闭即销毁。

## 6. 范围

**当前工作模式：** Windows / macOS 桌面外壳、工作面板、五种状态、多工具适配器、任务列表、静音/专注、托盘、开机启动、历史、用量日历。

**下一刀工作模式：** 本机供应商 / Key 管理（Codex、Gemini CLI、Grok CLI）。不依赖宠物模式，也不等待云端备份。

**更后：** 可选云端备份；宠物模式、模式切换、更完整的 macOS 体验、多屏记忆、声音、自动更新。
