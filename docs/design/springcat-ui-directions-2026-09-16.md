## 产品判断

建议把 SpringCat 定义为给 vibe coding 使用的桌面工具台：常驻入口负责感知，展开后的工作台负责处理。任务监听是第一项能力；后续用来降低上手成本、解决 vibe coding 过程问题的能力，共享同一个入口、通知优先级与工作台，避免每增加一个功能就增加一个浮窗。

常驻形态承担感知，展开面板承担处理，独立工作空间承担长内容。用量日历等需要长时间阅读的页面适合独立窗口。胶囊只呈现当前最重要的一件事，不能承担整个产品的信息架构。

## 三个方向

### A · 静谧状态岛

石墨黑表面、固定品牌锚点、一点状态色。静止时约 48px；短摘要约 264×52px；主动展开约 344px 宽。尺寸是设计起点，需要结合桌面缩放与显示器边缘验证。

适合保留现有产品辨识度，优先改善低打扰体验。任务由「需要你 → 进行中 → 最近完成」排序。主要操作写为「返回对话」，避免让只读监听器看起来能够直接授权来源工具。

### B · 侧边工作台

浅色表面，从屏幕侧边向内展开；边缘锚点稳定。展开后约 372px 宽，内容按「动态 / 动作 / 回顾」组织。

适合产品后续扩展。动态承接当前监听与任务列表；动作是未来的快速记录、打开工作区、工作流等能力；回顾承接历史与已有用量统计。概念中的未来能力必须明确标注，不能在当前版本显示为可执行能力。

### C · 桌面伴侣

暖白表面、极简猫咪轮廓和轻微表情变化。任务层级和交互规则与工作模式一致。通过表情和文案建立品牌感，持续晃动、跳跃与游戏化内容不进入默认体验。

适合强调 SpringCat 的陪伴属性。可以后续作为同一架构的外观模式。

### 推荐组合

根据用户补充的空间约束，顶部常驻与 macOS 刘海区域适配是首要场景。采用 A 的小体积常驻形态，借用 B 的功能分层；完整工作台从当前锚点展开，顶部模式向下展开。侧边位置作为备选，C 作为可选外观。

## 顶部位置约束（用户反馈后补充）

- 无刘海屏幕：工作区顶部居中，避开系统菜单栏 / 任务栏。静止时可用约 112–144×28–32 的短胶囊，摘要约 220–280×36–44，主动展开时再增加高度。球形可作为用户选择的更小状态。
- 有刘海的 Mac：沿用硬件刘海的中心线；静止时主体与刘海同色，可仅露出约 4–6 的下沿。摘要和交互内容从刘海下方显露，硬件摄像头区域不放文字或按钮。需要提供菜单栏入口或快捷键作为细小下沿之外的触发途径。
- 侧边：仍可用球形入口，短摘要向屏幕内侧生长，完整面板继续向内展开。
- 顶部模式的锚点是顶部中心，不把左上图标固定规则机械套用过来；球 / 胶囊 / 面板共享中心轴，上边界稳定，宽度向两侧变化，高度向下变化。
- 顶部尺寸单位按平台解释：macOS 使用逻辑点，Windows 使用设备无关尺寸并跟随系统缩放。上述数值是设计范围，刘海宽高必须按当前屏幕实际安全区域读取，不能写死为统一尺寸。
- 在全屏、菜单栏自动隐藏和多屏切换时，按当前屏幕的可见区域重新布局；最终行为需原生验证。不能把一个装饰性刘海示意当作已验证的系统集成。

定位结论：球与胶囊的小体积常驻价值必须保留。新增能力影响的是用户主动展开后的内容结构，不能使常驻入口不断膨胀。

## 交互合同

- 球 / 紧凑入口：单击直接打开工作台；悬停约 180ms 后显示短摘要；离开约 220ms 后收回悬停摘要。
- 胶囊：只呈现一条优先事项；单击进入工作台。用户阅读时不轮播标题。
- 工作台：主动打开后保持展开；显式收起、Escape 或有清晰规则的外部点击关闭；不因一条新事件打断阅读。
- 通知：后台执行仅更新状态；普通完成短暂提示并保留未读；等待确认和失败保留待处理标记。自动通知不强制展开完整工作台。
- 快速反向操作：保留当前速度与几何状态，立即调整目标；不丢弃第二次点击。
- 键盘：主要入口与操作可聚焦；收起后将焦点还给入口；隐藏内容不可进入 Tab 顺序。
- 减少动态效果：尊重系统偏好，以即时几何更新或短淡入淡出替代空间运动。

悬停时间是调试起点，不是苹果官方参数。触屏与键盘仍可直接点击或激活入口，不依赖悬停。

## 动效合同

1. 一个连续的外轮廓；品牌图标与屏幕空间锚点固定。左侧向左收束，右侧向右收束，顶部围绕中心收束。
2. 外壳尺寸、位置与圆角由一个可打断的动画状态驱动。常规展开取消小球横穿和整圈滚动。
3. 内容与外壳分层。文字保持正常尺寸，仅使用透明度与小幅位移；收起时先撤去内容，外壳连续回到入口。
4. 展开约 300–380ms、收起约 220–280ms、内容错开约 60–90ms，作为首轮试验范围；弹簧的最终稳定时间取决于距离和中断状态，不承诺固定值。
5. 原生窗口先准备绘制空间，视觉运动在内部进行，结束后提交必要的窗口尺寸。透明区域的命中范围必须与可见界面相符，避免挡住其他应用。
6. 玻璃只用于表达浮层关系。主体文字保持足够对比度，减少大面积模糊、高光和会持续吸引注意力的装饰。

## 当前实现的代码证据

以下来自当前工作区源码与浏览器演示。没有进行原生桌面录屏或帧时间测量；不能据此声称已确认每次卡顿的成因。

- `src/components/work-panel/panel-motion.ts` 的 `openPlan`：完整展开的 hold 合计 616ms，尚未包含原生窗口准备及额外绘制等待。
- `src/app/OverlayShell.svelte` 的 `setLayout`、`onOrbClick` 附近：busy / flow 条件会丢弃动画中的切换意图。
- `src/components/work-panel/WorkPanel.svelte` 的非顶部 closing/icon 规则：`left: calc(50% - 24px)` 让外壳收向中心，而关闭计划让球回到边缘，收束锚点不一致。
- `OverlayShell` 传入 `fillWindow`；`WorkPanel` 在该模式下使用 `100%` 宽度，绕过 `widthOverride`。这使预期的视觉宽度控制未生效，桌面窗口跳宽需要实机验证。
- 折叠 JS 等待 230ms，而相关外壳 CSS 使用 280ms，内容淡出使用 260ms，存在收尾时间不一致。
- 宽高、位置、裁剪、阴影及背景模糊同时变化，不能仅凭 CSS 或注释认定会稳定达到 60fps。

## 落地顺序与验收

先修宽度控制与收束锚点，再用可打断动画替代分段阻塞流程，最后调节材质、时长和通知策略。

验收至少覆盖：左右顶部吸附；球、胶囊、工作台之间往返；快速重复点击与 Escape；悬停后立即离开；任务在动画中完成；125% / 150% 桌面缩放；多屏边缘；减少动态效果。浏览器原型只能验证视觉与交互意图，最终需在 Windows WebView2 与 macOS 原生窗口录屏检查闪烁、裁剪、输入延迟和帧时间。

本次概念原型已完成：脚本语法检查；浏览器快速反向切换及 Escape；三个设计方向切换；任务详情的演示反馈；736px 与 360px 宽度视觉检查；控制台未见错误。系统缩放、多屏与原生性能属于集成阶段验证项。原型增加第三条示例任务后为内容留出了更高的面板空间，具体高度可随内容调整。
